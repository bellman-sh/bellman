# Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `docs.bellman.sh` serves Bellman's documentation from an Astro Starlight site in `docs-site/`: fourteen hand-written pages, and a tool reference generated from the server's own tool list that `npm test` keeps current.

**Architecture:** `scripts/docs-reference.ts` lists the tools through the in-memory MCP client the tests use (the server's tools, and the tools a hook-mode bridge adds) and renders one Markdown page per server tool plus one page for the bridge's. `scripts/docs-gen.ts` writes those pages; `tests/docs-reference.test.ts` renders them again and compares byte for byte. `docs-site/` is a separate npm project whose `astro build` fails on a broken internal link; an assets-only Worker, `bellman-docs`, serves its output at `docs.bellman.sh`, and `.github/workflows/docs.yml` builds it on pull requests and deploys it from main.

**Tech Stack:** TypeScript, vitest, `@modelcontextprotocol/sdk` (in-memory transport), Astro 7.3.8, `@astrojs/starlight` 0.42.6, `starlight-links-validator` 0.27.0, wrangler 4.132.0 (Workers static assets), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-15-docs-site-design.md`

## Global Constraints

- The site lives in `docs-site/` with its own `package.json` and lockfile; the server's dependencies do not change (D1).
- Exact pins in `docs-site/package.json`: `astro` `7.3.8`, `@astrojs/starlight` `0.42.6`, `starlight-links-validator` `0.27.0`, and `wrangler` `4.132.0` (the version the root lockfile resolves) as a devDependency. No `sharp`: the site has no images to optimise and builds without it.
- `docs-site` declares `"engines": { "node": ">=22.12.0" }`, Astro 7.3.8's floor. Astro 7.4.0 (released 2026-10-15) needs Node ≥ 22.22.0, which this machine's 22.16.0 is not; do not move past 7.3.x without raising the floor.
- Served at `docs.bellman.sh` by an assets-only Worker named `bellman-docs`, `[assets]` pointing at `./dist` with `not_found_handling = "404-page"`, the hostname attached as a custom domain (D2, "Build, deploy and checks").
- Pages are Markdown (`.md`) under `docs-site/src/content/docs/` (D3). A page's sections are `##` headings: Starlight renders the frontmatter `title` as the page's only `#`.
- `docs-site/src/content/docs/reference/tools/*.md` and `reference/bridge-tools.md` are generated by `npm run docs:gen`. Never edit them by hand; edit the tool in `src/`, then regenerate.
- Every script that runs the server runs `build:ui` first (CLAUDE.md), `docs:gen` included. In a fresh workspace run `npm run build:ui` once before any bare `npx vitest run`.
- A room holds many members. No page, comment, test name or commit message says "two sessions" or "the other session"; write members, the room, peers (CLAUDE.md, "Writing").
- No "load-bearing", no phrase built on "worth", no "structural" or "structurally", anywhere this plan has you write prose.
- Out of scope (spec): an HTTP API reference, self-hosting (#211), the hosted seat, handles. A page names an HTTP route only where the README does and no tool or panel screen covers it, in one sentence, with no request or response reference.
- Every number or name a page states comes from the symbol its task cites, read in the code, never from the site's pages: they say "eleven tools" and "up to 1,000" members, and the server has twelve tools and a ceiling of 5,000.
- Internal links are root-relative with a trailing slash (`/guides/rooms/`). A page links only to the generated reference and to pages earlier tasks wrote: `starlight-links-validator` fails the build on a link to a page that does not exist yet, and the page tasks are ordered so every link points back.
- Pages address the reader as "you". A prompt to an agent goes in a ` ```text ` block, a shell command in ` ```bash `, configuration in ` ```json ` or ` ```yaml `. No spec decision ids (D1…), ADR numbers or plan task numbers in page text.
- Edit files with the Edit or Write tool, never `perl -i` or `sed -i`.
- This is a jj workspace with no `.git`. Commit with `jj commit -m "<message>" <paths>`, naming only the task's files, after `jj diff --stat` shows exactly them. Commits are signed. Do not push.
- `npm run verify` passes before the commits of Tasks 1–3, and once more after Task 18. Tasks 4–17 change only Markdown under `docs-site/` (and two sidebar lines); their checks are the docs build and the writing test.
- Execution: subagents run the tasks in order. No per-task review; one whole-branch review after Task 18.

## Review Focus

1. A reader copies a quoted value (`"html"`, `"surface"`) from a tool page: they get straight quotes, as the tool wrote them, not “html”. Astro's smartypants is on by default; `markdown.smartypants: false` in Task 3, checked on the built page in Task 3 and on every pull request by Task 18.
2. A tool's multi-line description (the `type` list in `bellman_send`, the `Args:` blocks) keeps its lines instead of collapsing into one paragraph. Pinned by the exact-page test in Task 2 (each line ends in two spaces); the `<br>` count on the built `bellman_send` page is checked in Task 3 and by Task 18.
3. A tool is removed or renamed: its old page does not survive at the old URL or in the sidebar. `docs:gen` deletes tool pages it did not write, and the drift test in Task 2 lists orphans.
4. A `|` or a newline in a parameter's description: the table row stays one row with the text intact (`\|`, newline to a space). Pinned by the exact-page test in Task 2.
5. A `<` or `&` inside a backtick code span in tool text is shown as written, not as `&lt;`: an entity is literal inside a code span. Pinned by the `escapeProse` test in Task 2.

 * The generated reference on docs.bellman.sh (docs site spec, "The generated reference"): a page per
 * server tool and one for the bridge's own, rendered from the tools as a client lists them.
 * scripts/docs-gen.ts writes this same render, so the drift test is byte-exact: change a tool's title,
 * description, schema or annotations without `npm run docs:gen`, and it fails.
 */

import { join } from "node:path";
import { describe, expect, it } from "vitest";
import type { Tool } from "@modelcontextprotocol/sdk/types.js";
import {
  BRIDGE_PAGE, CONTENT_DIR, TOOLS_DIR, bridgePage, escapeProse, labelOf, referencePages, toolPage, typeOf,
} from "../scripts/docs-reference.js";
import { listServerTools } from "./helpers/tool-lists.js";

const fixture: Tool = {
  name: "bellman_example",
  title: 'Try the "example": a fixture',
  description: "Do one thing <safely> & well.\n\nArgs:\n  - mode: `<mode>` picks it\n    and this line continues it",
  inputSchema: {
    type: "object",
    properties: {
      mode: { type: "string", enum: ["fast", "slow"], default: "fast", description: "How | quickly\nit runs" },
      brief: {
        type: "object",
        description: "What you know",
        properties: {
          goal: { type: "string", description: "One <line>" },
          notes: { type: "array", items: { type: "string" }, default: [] },
        },
        required: ["goal"],
      },
    },
    required: ["brief"],
  },
  annotations: { readOnlyHint: false, destructiveHint: false },
};

describe("escaping tool text", () => {
  it("escapes & and then <, so <your key> renders as written", () => {
    expect(escapeProse("Bearer <your key> & co")).toBe("Bearer &lt;your key> &amp; co");
    expect(escapeProse("&lt;")).toBe("&amp;lt;");
  });

  // Review Focus 5: inside a code span an entity is shown literally, so a code span keeps its text.
  it("leaves a code span as written", () => {
    expect(escapeProse("`<name>` and <name> & `a&b`")).toBe("`<name>` and &lt;name> &amp; `a&b`");
  });

  it("shows bellman_start's <role> as text, not as a tag", async () => {
    const page = (await referencePages()).get(`${TOOLS_DIR}/bellman_start.md`)!;
    expect(page).toContain("&lt;role>");
    expect(page).not.toContain("<role>");
  });
});

describe("a tool's label", () => {
  it("comes from readOnlyHint, then destructiveHint, with MCP's defaults for a hint left out", () => {
    expect([
      labelOf({ readOnlyHint: true }),
      labelOf({ readOnlyHint: true, destructiveHint: true }),
      labelOf({ readOnlyHint: false, destructiveHint: false }),
      labelOf({ readOnlyHint: false, destructiveHint: true }),
      labelOf({ readOnlyHint: false }),
      labelOf(undefined),
    ]).toEqual(["Reads", "Reads", "Writes", "Destructive", "Destructive", "Destructive"]);
  });

  it("labels the real tools by their own annotations", async () => {
    const pages = await referencePages();
    const label = (name: string) =>
      pages.get(`${TOOLS_DIR}/${name}.md`)?.match(/^\*\*(Reads|Writes|Destructive)\*\*$/m)?.[1];
    expect({ sync: label("bellman_sync"), send: label("bellman_send"), evict: label("bellman_evict") })
      .toEqual({ sync: "Reads", send: "Writes", evict: "Destructive" });
  });
});

describe("a parameter's type", () => {
  it("reads a type, an array's items, a list of types and a union", () => {
    expect([
      typeOf({ type: "string" }),
      typeOf({ type: "array", items: { type: "string", enum: ["a"] } }),
      typeOf({ type: "array" }),
      typeOf({ type: ["boolean", "null"] }),
      typeOf({ anyOf: [{ type: "object" }, { type: "object" }] }),
      typeOf({ anyOf: [{ type: "string" }, { type: "null" }] }),
      typeOf({}),

});

describe("a tool page", () => {

      'title: "bellman_example"',
      'description: "Try the \\"example\\": a fixture"',
      "---",
      "",
      "<!-- Generated by npm run docs:gen from each tool's own definition: edit the tool in src/, then run it again. -->",
      "",
      "**Writes**",
      "",
      "Do one thing &lt;safely> &amp; well.  ",
      "",
      "Args:  ",
      "  - mode: `<mode>` picks it  ",
      "    and this line continues it  ",
      "",
      "## Parameters",
      "",
      "| Name | Type | Required | Description | Values | Default |",
      "| --- | --- | --- | --- | --- | --- |",
      '| `mode` | string | no | How \\| quickly it runs | `fast`, `slow` | `"fast"` |',
      "| `brief` | object | yes | What you know | — | — |",
      "| `brief.goal` | string | yes | One &lt;line> | — | — |",
      "| `brief.notes` | string[] | no | — | — | `[]` |",
      "",
    ].join("\n"));
  });

  it("says so when a tool takes no parameters", () => {
    expect(toolPage({ ...fixture, inputSchema: { type: "object", properties: {} } }))
      .toContain("## Parameters\n\nThis tool takes no parameters.\n");
  });

  it("takes its description from the tool's title, then its annotations' title, and refuses a tool with neither", () => {
    expect(toolPage({ ...fixture, title: undefined, annotations: { title: "From the annotation" } }))
      .toContain('description: "From the annotation"');

  it("heads each tool with its name and title, and puts its parameters one level down", () => {
    const page = bridgePage([fixture]);
    expect(page.startsWith('---\ntitle: "Bridge tools"\n')).toBe(true);

    const pages = await referencePages();
    const server = (await listServerTools()).map((t) => t.name).sort();
    const toolPages = [...pages.keys()]
      .filter((path) => path.startsWith(`${TOOLS_DIR}/`))
      .map((path) => path.slice(TOOLS_DIR.length + 1, -".md".length))
      .sort();
    const bridgeTools = [...pages.get(BRIDGE_PAGE)!.matchAll(/^## (\S+)$/gm)].map((m) => m[1]);
    expect({ toolPages, bridgeTools, size: pages.size }).toEqual({
      toolPages: server,
      bridgeTools: ["bellman_wait", "bellman_whoami", "bellman_upload"],
      size: server.length + 1,
    });
  });

  it("is committed as npm run docs:gen writes it", async () => {
    const pages = await referencePages();
    const stale = [...pages]
      .filter(([path, text]) => {
        const file = join(CONTENT_DIR, path);
        return !existsSync(file) || readFileSync(file, "utf8") !== text;
      })
      .map(([path]) => path);
    const dir = join(CONTENT_DIR, TOOLS_DIR);
    const orphans = (existsSync(dir) ? readdirSync(dir) : [])
      .filter((name) => name.endsWith(".md"))
      .map((name) => `${TOOLS_DIR}/${name}`)
      .filter((path) => !pages.has(path));
    expect({ stale, orphans }, "run npm run docs:gen").toEqual({ stale: [], orphans: [] });
  });
});

- [ ] **Step 5: Write `scripts/docs-reference.ts`**

No side effects at import: the test imports it. A doc comment says it is the shared render of `docs-gen.ts` and the drift test. The rules the tests do not spell out:

- `CONTENT_DIR` is `fileURLToPath(new URL("../docs-site/src/content/docs/", import.meta.url))`, so the script and the test agree whatever the working directory.
- `escapeProse` splits the text on single-backtick code spans, `` /(`[^`\n]*`)/ ``, and in the parts outside them replaces `&` with `&amp;` and then `<` with `&lt;`.
- `labelOf`: `readOnlyHint === true` is Reads; otherwise `destructiveHint === false` is Writes; otherwise Destructive. That is MCP's reading of a hint left out (`readOnlyHint` false, `destructiveHint` true).
- `typeOf`: a union is its branches' types, deduplicated, joined with " or "; a list of types is joined with " or "; an array is its items' type followed by `[]`, `any[]` with no items; a type is itself; a schema with none of these is `any`.
- `toolPage(tool)` is the fixture's expected output, shaped for any tool: frontmatter values through `JSON.stringify` (a JSON string is a valid YAML double-quoted scalar), the frontmatter `description` from `tool.title ?? tool.annotations?.title` and an `Error(`${tool.name} has no title`)` when both are missing; the banner comment exactly as the test has it; the label in bold; the description through `escapeProse` with every line that has text ending in two spaces (`line.trimEnd() + "  "`) and every other line empty, which is a Markdown hard break inside a paragraph and is dropped at a paragraph's end; `## Parameters`; then the table, or `This tool takes no parameters.` when `inputSchema.properties` is empty.
- Table rows walk `properties` depth first in listed order: a property with `properties` of its own is followed by its children, named with dots (`brief.agent.provider`). A union such as `bellman_start`'s `manifest` is one row. Columns: the name in backticks; `typeOf`; `yes` or `no` from the parent's `required`; the description through `escapeProse` with each newline as a space; the values, `enum ?? items.enum`, each in backticks, joined with ", "; the default as `JSON.stringify` in backticks; `—` for an empty cell; and every `|` in a cell written `\|`.
- `bridgePage(tools)`: frontmatter with `title: "Bridge tools"` and `description: "The tools the local bridge adds to the server's."`, the same banner, then this paragraph, then each tool as `## <name>`, its title through `escapeProse` in `*…*`, and the same body as a tool page from the label down, with `### Parameters`:

  > The local bridge runs on your machine. The Claude Code plugin, the npm package's `bellman-channel` and the Claude Desktop bundle each start one. It lists every server tool and adds the tools below. `bellman_wait` is listed only when the bridge runs in hook delivery, as the plugin and the bundle do.

Cover:
- **Pair and swarm.** A pair room holds two; a swarm room holds as many members as you invite, up to 5,000, the same on every plan (`capacityOf` and `ROOM_MEMBER_CEILING` in `src/store.ts`). The free plan starts pair rooms only (`ENTITLEMENTS` in `src/auth.ts`).

A public room's permanent code is the exception, in one sentence.
- **Joining: preview, then confirm.** `bellman_connect` previews; `bellman_confirm` ships your brief and seats you in the role the previewed code carried. A joiner is handed the briefs of the 25 members heard from most recently (`BRIEFS_ON_JOIN` in `src/tools/confirm.ts`).

A full room refuses a new code. A caution that `invite` reaches every role the manifest declares, including one more capable than the inviter's.
- **Removing a member.** `bellman_evict` is the creator's alone and no role grants it. It retires that seat's live code; the person keeps reading the room's history up to the `member_evicted` event; it is not a ban, and a live code seats them again.
- **Leaving.** `bellman_leave` tells the room; the room closes when its last member leaves.
- **How long a room lasts.** No expiry: a room ends when its last member leaves, or after 90 days in which nobody in it was seen (`ABANDONED_AFTER_MS` in `src/store.ts`). `bellman_rooms` lists the rooms you hold a seat in, with members, roles, presence and live codes.

- [ ] **Step 1: Write the smoke check**

`docs-site/smoke.sh`:

```sh
#!/bin/sh
# After a deploy: the home page and one tool page answer 200, and the tool page shows bellman_start's
# <role> as text. Usage: sh ./smoke.sh [base URL], https://docs.bellman.sh by default. A new custom
# domain can take minutes to answer, so each page gets TRIES attempts (default 30), ten seconds apart.
set -eu
base=${1:-https://docs.bellman.sh}
tries=${TRIES:-30}
for path in / /reference/tools/bellman_start/; do
  n=0
  while :; do
    code=$(curl -s -o /dev/null -w '%{http_code}' "$base$path" || true)
    [ "$code" = "200" ] && break
    n=$((n + 1))
    [ "$n" -ge "$tries" ] && { echo "::error::$base$path answered $code"; exit 1; }
    sleep 10
  done
done
curl -sf "$base/reference/tools/bellman_start/" | grep -q '&lt;role&gt;' \
  || { echo "::error::$base/reference/tools/bellman_start/ does not show <role> as text"; exit 1; }
echo "smoke: $base serves the home page and bellman_start"
```

- [ ] **Step 4: Write the workflow**

`.github/workflows/docs.yml`:

```yaml
name: Docs

# docs.bellman.sh: built on every pull request that could change it, deployed from main. A tool
# change that regenerates the reference also touches docs-site/, which is what usually triggers this.
on:
  push:
    branches: [main]
    paths: ["docs-site/**", "src/tools/**", ".github/workflows/docs.yml"]
  pull_request:
    paths: ["docs-site/**", "src/tools/**", ".github/workflows/docs.yml"]

# A fork PR gets no secrets and no write access. The build needs neither.
permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: docs-site
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: docs-site/package-lock.json

      - run: npm ci

      # starlight-links-validator fails this on a broken internal link.
      - run: npm run build

      # The pages as a reader gets them. Each line reads one tool's own text, so a change to that
      # text can move what it looks for: bellman_start writes <role>, and bellman_send writes
      # kind: "html" and lists its types a line each.
      - name: The built pages show tool text as written
        run: |
          set -eu
          page=dist/reference/tools
          grep -q '&lt;role&gt;' "$page/bellman_start/index.html" || { echo "::error::bellman_start's <role> is not shown as text"; exit 1; }
          grep -q 'kind: "html"' "$page/bellman_send/index.html" || { echo "::error::bellman_send's quotes were curled"; exit 1; }
          [ "$(grep -o '<br>' "$page/bellman_send/index.html" | wc -l)" -ge 10 ] || { echo "::error::bellman_send's description lost its line breaks"; exit 1; }

      # The deploy job's own command, which needs no credentials.
      - run: npx wrangler deploy --dry-run --outdir .wrangler/dry-run

  deploy:
    # Only a push to main that already built.
    needs: build
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    # Never let two deploys race; a queued one waits rather than being dropped.
    concurrency:
      group: deploy-docs
      cancel-in-progress: false
    defaults:
      run:
        working-directory: docs-site
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: docs-site/package-lock.json

      - run: npm ci
      - run: npm run build

      # Fail loudly rather than letting wrangler guess at an account.
      - name: Require deploy credentials
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
        run: |
          if [ -z "$CLOUDFLARE_API_TOKEN" ] || [ -z "$CLOUDFLARE_ACCOUNT_ID" ]; then
            echo "::error::CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID must be set as repository secrets"
            exit 1
          fi

      # The server deploy's token. If it cannot attach the custom domain, the first deploy is the
      # owner's, by hand; every later one only uploads.
      - run: npx wrangler deploy
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}

      - name: Verify the deployment
        run: sh ./smoke.sh https://docs.bellman.sh
```
