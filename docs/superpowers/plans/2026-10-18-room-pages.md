# Room Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This plan runs with subagents and **one whole-branch review per PR, at the end**: no per-task review steps, whatever a skill says.

**Goal:** A public room reads as a page of its `text` items, newest first, and each item on its surface has a URL of its own, `bellman.sh/r/<room>/<item>`, with a head that link previews read. A request that prefers `text/markdown` gets the room or the item as Markdown, `bellman.sh/r/<room>/feed.xml` is the room's Atom feed, and the room's creator chooses whether it opens on its canvas or as a page.

**Architecture:**
- **Part 1, the server.** A surface row gains `createdAt`: `applySurfaceWrite` stamps it on a key's first write and carries it across edits, and `createdAtOf` reads a row from before it as created at its `at`. `surfaceItem` gives every read of an item `created_at` and `changed_at`. The room's record gains `publicView`, `canvas` or `page`, which the creator sets with `PUT /rooms/:id/view` and which the public room read and the panel's room read carry as `view`.
- **Part 2, the dash.** The public room page gains a Page view beside Canvas and Log, an item route `/r/$roomId/$itemKey`, and, for the creator, an "Opens as" control. Its Worker answers `/r/<room>/<item>` with the item's head and a plain summary, answers the room and item paths in Markdown when the request prefers it, and serves `/r/<room>/feed.xml`, all from the public reads it already makes and keeps a minute (`apiRead`).

**Tech Stack:** TypeScript. bellman: Cloudflare Workers and Durable Objects, vitest 5 for the root program, vitest 4 with `@cloudflare/vitest-pool-workers` for `worker-tests/`. The dash: Vite 8, React 19, TanStack Router, react-markdown, vitest 5; its Worker uses `HTMLRewriter` and the Cache API and is tested in workerd (`worker-tests/`, its own package).

**Spec:** `docs/superpowers/specs/2026-10-18-room-pages-design.md` (approved). D5 follows D1 of `docs/superpowers/specs/2026-10-17-agent-readable-files-design.md` (on the `bellman-agent-files` branch). The public room page this extends is Part 1 of `2026-10-17-public-rooms-on-bellman-sh` (merged in the dash as #58); the item canonical builds on that plan's Part 2a, which adds `public_url` to the room read.

## Global Constraints

- **Writing.** A room holds many members: never "two sessions" or "the other session"; say members, the room, or peers. Never "load-bearing", any "worth …" phrase, or "structural", in code, comments, docs, commit messages or the PR.
- **Store methods** are async, every one. A new field or method goes into `MemoryStore`, the Durable Objects store and `tests/helpers/store-contract.ts`, which runs against both.
- **Generated files.** `src/ui/assets.ts` is generated by `npm run build:ui`: edit `ui/`, never it. `plugin/bridge/*.mjs` are rebuilt only by release PRs, and neither PR here is one. The docs site's tool pages are written by `npm run docs:gen` and pinned by `tests/docs-reference.test.ts`; never edit them by hand.
- **Non-ASCII in TypeScript** is a braced escape: U+00B7 is `\u{B7}`, U+2026 is `\u{2026}`. JSX text reads no escape, so there it goes in a string expression: `{" \u{B7} "}`.
- **Tools.** Edit files with the Edit or Write tool, never `perl -i` or `sed -i`. Never call a `graph_*`, dual-graph or `bellman_*` tool. Never bypass commit signing: a commit that hangs or says "incorrect passphrase supplied" is a stop, reported to the lead.
- **Reviews.** One whole-branch review per PR, after its last task. No task has a review step.
- **Untrusted text stays text.** Item titles and bodies, room names and purposes, and member names reach HTML only through `HTMLRewriter`: `setInnerContent(…)` or `append(…, { html: false })` for text, `setAttribute` through the Worker's `attribute()` helper (which escapes `&`) for attribute values. Only constant markup goes in with `{ html: true }`. Markdown and Atom escape what their formats need (R22).
- **The Worker's cache.** Each public read is kept at most a minute (`CACHE_SECONDS = 60`). Nothing is kept for a failure, a timeout or a body of the wrong shape.
- **Dates on the wire** are ISO 8601 (`new Date(ms).toISOString()`). Shown to a reader they are UTC days written as the site writes dates, `18 October 2026` (R10).
- **Hosts and paths.** The room is `https://bellman.sh/r/<room>`, an item `https://bellman.sh/r/<room>/<item>`, the feed `https://bellman.sh/r/<room>/feed.xml`. Every `/r/` path on `dash.bellman.sh` answers 301 to the same path and query on `bellman.sh`. An item key is the server's surface key grammar, `^[a-z][a-z0-9_]{0,30}$`.
- **Names on the wire.** The record's field is `publicView`, `"canvas"` or `"page"`, `"canvas"` when unset; the reads' field is `view`. An item's dates are `created_at` and `changed_at`.
- **The head of an item's page** (spec section 1): `<title>` is the item's title, a space, U+00B7, a space, the room's name; `description` and `og:description` are the body's first paragraph cut to about 200 characters at a word (R17); `og:title` is the item's title; `og:url` and the canonical link are the item's URL under the room read's `public_url`; `og:image`, `og:site_name` and `twitter:card` are the room page's. An untitled `text` item uses the room's name (R15).
- **Markdown and the feed.** Markdown is `text/markdown; charset=utf-8`; the feed is `application/atom+xml; charset=utf-8` with `Cache-Control: max-age=60`. Every answer on a room's or an item's path carries `Vary: Accept`. A room that is not public, or a key that names no item, is a 404 in every form.
- **Repos.** bellman is jj (`jj commit`); the dash is git, on a branch from `origin/main`. Every commit is signed. Nothing reaches `main` but through a PR.
- **Order.** Part 1 merges and deploys first. Part 2 starts after that deploy and after public rooms Part 2a has shipped `public_url`.

## Rulings

Every place the spec is silent, or the code disagrees with it, and what this plan does.

- **R1. No hydrate step reads surface rows, so the default is read where a row is read.** `hydrateStoredSession` hydrates the session record only. A surface row is read raw, and its older defaults are applied by its readers (`r.blob ?? null` and `r.shape ?? null` in `surfaceItem`). `createdAtOf(row)` is `row.createdAt ?? row.at`, in `src/surface.ts`, and `applySurfaceWrite` and `surfaceItem` both use it. `SurfaceRow.createdAt` is optional, because stored rows lack it. No row is rewritten.
- **R2. An edit of a row from before this carries that row's `at` as its `createdAt`.** That is the oldest time the store knows for the key, so after one edit an old item reads written at its last change before this shipped (the spec's third risk).
- **R3. `at` stays on every read of an item, beside `changed_at`.** They are the same instant. The dash's canvas (`Attribution`), the MCP App and agents read `at`; renaming it would break the live dash between the two PRs. Only `bellman_surface`'s description lists an item's fields, so it is the one tool text that changes.
- **R4. `created_at` and `changed_at` sent back on a write are refused by name, as `cursor` and `at` are.** `SurfaceItemShape` is strict. The surface guide, the canvas skill and the shape's comments say the item goes back without all four. The dash's `toWrite` (`src/lib/canvas.ts`) copies named fields only, so its editor already leaves them out.
- **R5. An item's author is its envelope's origin, the member who last wrote it.** A row keeps only its last writer (`byMemberId`, `byLabel`), so a post another member edits shows that member. A signed creator's number reads `@handle`, as everywhere on the public page (`relabel` and `nameFor` in the dash, `namesIn` in the Worker).
- **R6. `publicView` lives on the session record beside `publicName`.** `Session.publicView: PublicView` is required; `hydrateStoredSession` reads `"page"` as `"page"` and anything else, absence included, as `"canvas"`. Its constructors are `bellman_start` and the tests' `session()` fixture.
- **R7. The route is new: `PUT /rooms/:id/view`.** No route sets "a room's public settings" today: the name has a tool (`bellman_public_name`), and the byline and unpublishing have routes of their own. D7's "no new server route" is about rendering: the page, the Markdown and the feed come from the public reads that exist. A setting the creator changes needs a write, and none exists for it. It admits as `writeByline` does (401, the CSRF check, one 404, 403 for a member who is not the creator), then bounds and parses the body (413, 400) and answers 409 `room_not_public` for a room that is not public. It files no audit row, as neither the byline nor the unpublish route does. A closed public room may still change it, since it reads until it is deleted. No tool sets it, so no agent-facing text changes and `extension/manifest.json` stays.
- **R8. `view` is on the panel's room read, `GET /rooms/:id`, beside `mine` and `signed`, and not inside `roomPreview`.** The spec says "the creator's preview". `roomPreview` is also the room block of five tools (`bellman_start`, `bellman_connect`, `bellman_confirm`, `bellman_surface`, and `bellman_rooms` through `roomSummary`), so a field there would change five tools' returns and two tools' `Returns:` lines for a setting no tool sets. The read the creator's panel loads carries it beside `signed`, the other public setting only the creator's controls change, for every caller: the public read already tells anyone.
- **R9. `view` on the public room read is top level, beside `mode`,** outside the envelope: a value the server checked, not the creator's prose.
- **R10. Dates are UTC days, `18 October 2026`; "edited" shows when its UTC day is later than the written one.** The spec's "when later" at a day's grain: an edit the same day shows only "written". One helper, `datesLine`, serves the page, the item page, the Markdown and the summary.
- **R11. The page lists every kind but connectors.** A connector is drawn between its ends and has no title or place of its own. `text` items are articles, every other kind one line; all of them newest `created_at` first, ties by key.
- **R12. An item's page reads its room and surface once, in the route's loader, and does not poll.** The Page view polls as the canvas does.
- **R13. "A link to the same item on the canvas" is `/r/<room>?view=canvas&item=<key>`.** The read-only canvas fits its first view to that node with React Flow's `fitViewOptions.nodes`, as the member canvas's locate does.
- **R14. Three tabs, Canvas, Page and Log.** A tab for the room's own view links with no `view`, so the room's link stays clean; the others name theirs. `?view=` takes `canvas`, `page` and `log`, and wins over the setting.
- **R15. An untitled item's head.** For an untitled `text` item, `og:title` is the room's name (spec) and `<title>` is the room page's own, `<room> \u{B7} Bellman`, not the room's name twice. Any other kind uses its title, else its key, for both, and the room's description (its purpose, else `A public Bellman room.`) for `description`: a diagram's body is mermaid source and an html item's is a page, neither a description.
- **R16. An item's page carries a plain summary, as the room's page does.** In the app's root, replaced when the app loads: the title as `<h1>`, a line with the author and the dates, and for a `text` item each paragraph of its body (blocks between blank lines) as a `<p>` of text. A crawler that runs no script reads the post.
- **R17. The first paragraph, read line by line:** fenced lines (from a line starting with ```` ``` ```` or `~~~` to the next) and headings (`#` to `######` and a space) are passed over, the first run of other non-blank lines is the paragraph, its whitespace collapsed; an image or a link shows as its text, and `*` and backticks are dropped. Longer than 200 characters, it is cut at the last space within the first 201 (at 200 when there is none) and ends with U+2026. No prose gives null, and the head falls back to the room's description.
- **R18. Markdown and the feed read the room and its surface through `apiRead`.** An API failure, a timeout or a wrong shape answers 503, `text/plain`, `cache-control: no-store`, with nothing kept: the HTML page falls back to the app, which reads again, and a Markdown reader has no app. A 404 is a short Markdown body for a request that prefers Markdown and plain text for the feed.
- **R19. Negotiation is the agent-readable files spec's D1.** For each of `text/markdown` and `text/html`, its q is that of the most specific range that names it (the type, else `text/*`, else `*/*`, else 0). Markdown wins on a higher q, or on an equal q above 0 when its own entry comes before `text/html`'s; a wildcard names neither first. Media types compare without case. Only `/r/<room>` and `/r/<room>/<item>` negotiate. Every answer `publicRoomPage` gives, the 404s and failures included, carries `Vary: Accept`; the feed's does not, since it has one form.
- **R20. Headers.** Markdown and the feed carry `x-content-type-options: nosniff` and `content-security-policy: sandbox`, as the server's downloads do, so a browser shows peer text and never runs it. Markdown carries `cache-control: no-store`, as the HTML page does; the feed `max-age=60` (spec).
- **R21. The room's URL in Markdown and the feed is `canonicalOf(room)`,** the read's `public_url`, else the URL the request named (`PUBLIC_ROOM_BASE` and its key). An item's URL is the room's, a slash, and its key; the feed's ids are those URLs. The feed's `updated` is its newest entry's `changed_at`, or `1970-01-01T00:00:00.000Z` for a feed with none, since Atom requires one.
- **R22. Escaping.** Markdown: a room name, purpose, title or author name has its line breaks collapsed to a space, a heading's trailing `#`s are escaped with a backslash, and in an item's first line the room's name has `\`, `[` and `]` escaped with a backslash, so every post stays one section and the link stays a link; a body goes as written (spec). Atom: `&`, `<` and `>` in text, and `"` too in attributes, are escaped, and every character outside XML 1.0's `Char` production is dropped (C0 controls but tab, newline and carriage return; U+FFFE and U+FFFF; lone surrogates), so one pasted escape sequence cannot make the feed ill-formed for every subscriber.
- **R23. The room page's head names its feed:** `<link rel="alternate" type="application/atom+xml" href="<link>/feed.xml">`, written with the canonical link when the room has one, so a feed reader handed the room's link finds it.
- **R24. `feed.xml` never shadows an item:** a key has no dot. A second segment outside the key grammar, and a path of three or more segments, are the 404 with no API read.
- **R25. The ADR is numbered at merge:** `docs/adr/00NN-room-pages.md`. 0023 is read_context's, and public rooms 2a and 2b take the next two; this takes the next number free when Part 1 merges.
- **R26. The docs site's public rooms guide and the README change after Part 2 deploys** ("After this plan"): the page, item URLs, Markdown and the feed are the dash's, and would read false between the two PRs. Part 1's own docs (the surface guide, the canvas skill, ARCHITECTURE, the ADR) describe what Part 1 ships.
- **R27. The MCP App's mirror, `SurfaceItemWire` in `ui/src/types.ts`, stays:** it reads neither date, and a field the server adds does not break it.
- **R28. The dash and its Worker share one module of article rules,** `src/lib/article.ts`, with no `@/` import and nothing from `src/lib/api.ts`, which reads `import.meta.env` and cannot enter the Worker's program (`tsconfig.worker.json`). `src/lib/byline.ts` declares its byline shape itself for the same reason, so the Worker reuses `nameFor`.
- **R29. A post written in the dash's editor gets a key with a random suffix** (`slugKey(title)`, as today), so its URL reads `bellman.sh/r/blog/room_pages_k3j9x2`. A chosen URL means writing the post through `bellman_send` with the key. The spec asks for no editor change; see Open questions.

## Review Focus

The inputs most likely to bite a reader that no spec-driven test exercises, each pinned in the task named.

1. **An agent, or the dash's editor, editing an item by sending back what it read.** It now carries `created_at` and `changed_at` beside `cursor` and `at`. Expected: the server refuses each by name, the guide and the skill say to leave all four out, and the dash's `toWrite` drops both. Pinned in Task 2 (the refusal) and Task 7 (`toWrite`).
2. **A browser's and an agent's `Accept`.** A browser sends `text/html,…,*/*;q=0.8`, `curl` sends `*/*`, and agents send `text/markdown` with or without q-values or `text/html` beside it. Expected: HTML for the first two and for no header, Markdown only when it outranks HTML. Pinned in Task 12's table.
3. **A post with a footnote, read on the Page view.** The renderer scrolls the nearest `[data-note-body]`, which on the canvas is the card and on the page is not a scroll container, so the reference would do nothing. Expected: the page moves to the note. Pinned in Task 7.
4. **A post whose body holds a control character,** an escape sequence pasted from a terminal or a NUL. Expected: the feed stays well-formed XML for every subscriber, and the character is dropped there only. Pinned in Task 13.
5. **A room whose items were written before this ships.** Their rows have no `createdAt`. Expected: each reads written and changed at its `at`, orders by it, and after one edit keeps that `at` as written. Pinned in Task 1 (the row), Task 2 (the read) and Task 6 (the order and the dates line).

```markdown
# ADR 00NN — Room pages

**Date:** 2026-10-18 · **Status:** accepted · **Spec:** `docs/superpowers/specs/2026-10-18-room-pages-design.md` · **Plan:** `docs/superpowers/plans/2026-10-18-room-pages.md`

## Context

A public room read only as a canvas or a log, and nothing on its surface had a URL of its own. A room could not serve as a blog: nothing ordered its posts by when they were written, no post could be linked to, and there was no feed.

## Decision

1. **A surface row remembers when its key was first written** (spec D4). `applySurfaceWrite` stamps `createdAt` on a key's first write, keeps it across edits, and stamps it afresh when a removed key is written again. A row from before this reads its `at` as `createdAt` (`createdAtOf`); nothing rewrites it.
2. **Every read of an item carries `created_at` and `changed_at`,** ISO 8601, beside `at`, which stays: the members' reads, `bellman_surface`, and the public surface read. Sent back on a write, both are refused by name, as `cursor` and `at` are.
3. **A public room's creator chooses how its page opens** (D3): `publicView`, `canvas` or `page`, on the room's record beside `publicName`, `canvas` for a record from before it. `PUT /rooms/:id/view` sets it, the creator's alone and only while the room is public. `GET /public/rooms/:id` and `GET /rooms/:id` carry it as `view`; the tools' room block does not.
4. **The dash renders the rest** (D1, D2, D5, D7): the Page view, each item's URL `bellman.sh/r/<room>/<item>` with its own head, Markdown on request, and the Atom feed at `bellman.sh/r/<room>/feed.xml`, from the public reads its Worker already makes and keeps a minute. No server route serves a page.

## Consequences

- An old room's items read the two dates the same until each is edited, so its page orders them by their last change before this shipped.
- A post shows the member who last wrote it: a row keeps only its last writer.
- An agent that edits an item by sending back what it read leaves out four fields now: `cursor`, `at`, `created_at` and `changed_at`.
- No tool sets `view`; the dash's "Opens as" control is the one way.
- A rollback is a revert: code that does not know `createdAt` or `publicView` reads past both.
```
