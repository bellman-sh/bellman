# Orgs as a Real Object — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An org is a stored record with a name, an owner, a seat count and a standing, its members are the grants that name it, a team purchase creates it, and its admin adds and removes members through routes the control panel can call.

**Architecture:** The `Org` record lives in `RegistryDO` under `org:<orgId>`, beside the grants and their org index, so the seat check, the member write and its audit row are one transaction. Membership stays the `PlanGrant`; nothing new is derived from it. A lapsed subscription marks the org inactive and every grant in it resolves to `free` through one helper on the plan-resolution path. The admin's routes are a new `src/http/orgs.ts` on the audit routes' rules; the operator's are two paths in `src/oauth/routes.ts` on `operatorGate`.

**Tech Stack:** TypeScript, vitest (root program over `MemoryStore`; `worker-tests/` over real Durable Objects), Cloudflare Workers + Durable Objects, Stripe webhooks (already wired).

**Spec:** `docs/superpowers/specs/2026-10-21-orgs-and-sso-design.md`, decisions D1 to D8. PR 2 (D9 to D14) is a later plan.

## Global Constraints

- Every `BellmanStore` method is async, and every new one joins `tests/helpers/store-contract.ts` so both stores answer identically (CLAUDE.md, ARCHITECTURE invariant 1).
- A guarded write is one operation: `MemoryStore` must not `await` between its read and its write; `RegistryDO` runs both in `ctx.storage.transaction` and queues its audit rows through `this.driver.enqueue(txn, …)` inside it, delivering after with `deliverNow()` (ADR 0006).
- Writing methods nothing outside `RegistryDO` calls are `#private` (ADR 0006 consequences).
- Audit rows for an org are filed under `sessionId: "org:<orgId>"`, parties `[orgId]`, built with `auditRow` from `src/audit.ts`; a change that changed nothing files none (D8).
- An org name is trimmed and 1 to 80 characters; `seats` is an integer of at least 1; an org id passes `isOrgId` (D1, D7).
- "A room holds many members, not two": never write "two sessions" or "the other session" in comments, docs or commit messages (CLAUDE.md).
- Run `npm run build:ui` once in a fresh checkout before any vitest run: `src/ui/assets.ts` is generated and gitignored.
- Before the PR: `npm run verify` (typecheck, typecheck:worker, build, test, test:worker) must pass.

## Review Focus

1. An `email:` member claimed onto its subject at sign-in (`moveGrant`) must keep the org's seat count unchanged, so a full org does not refuse the next write for a move that added nobody — Task 2 pins it.
2. `PATCH /admin/orgs/:orgId` lowering `seats` below the members held keeps every member and refuses the next add — Task 2 pins it in the contract.
3. A `/org/members/:key` segment is percent-encoded (`email:a%40b.com`, `github%3A4242`); a segment that is not a valid encoding is 400, never a 500 — Task 7 pins it.
4. A `pro` grant in an org whose record is inactive resolves to `free` too: the rule is "inactive org, free plan", not "team becomes free" — Task 5 pins it.
5. A Stripe item whose `quantity` is 0, null or a non-integer counts as 1 seat; a subscription with no item naming the plan grants nothing and no org — Task 4 pins it.
