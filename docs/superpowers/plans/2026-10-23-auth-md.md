# auth.md agent registration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An agent holding only its user's email gets a Bellman access token through the auth.md v0.6.0 `service_auth` claim ceremony, and the AS metadata advertises it with an `agent_auth` block.

**Architecture:** A runtime-free module (`src/oauth/agent-auth.ts`) holds the records, constants and every decision (poll, approve, reissue). `MemoryAuthStore` and `AuthDO` both call those decisions inside one transaction per operation. `handleOAuth` in `src/oauth/routes.ts` gains the metadata, two JSON endpoints, the claim page and two `/token` grants.

**Tech Stack:** TypeScript, Cloudflare Workers + Durable Objects, vitest (`tests/`), vitest-pool-workers (`worker-tests/`).

**Spec:** `docs/superpowers/specs/2026-10-23-auth-md-design.md` (approved 2026-10-23, anonymous off). Read it before any task; D-numbers below refer to it.

## Global Constraints

- `npm run verify` passes before every commit (typecheck:ui, typecheck, typecheck:worker, build, test, test:worker, test:mod).
- Pure logic lives in runtime-free modules; `store.ts` and Workers-only code are not imported by vitest tests.
- `AuthDO` private methods use `#private`; every public `AuthDO` method is RPC and gets a forwarding method on `AuthStore`.
- Alarms are armed after a transaction, never inside it (`#armSweep(SWEEP_INTERVAL_MS)`).
- Errors on `/agent/*`: JSON `{error, error_description}` via `json()`. Errors on `/token`: `oauthError` (plus a `status` field for the two poll errors, D6).
- Pages render only Bellman's strings and the session label, through `escape()`. No peer content on this path.
- `main` moves only by merged PR. No push or PR without the user asking.

## Review Focus

1. A `login_hint` with capitals or surrounding spaces (`" Jesse@Example.dev "`) binds to `jesse@example.dev` and is approvable by a session holding `email:jesse@example.dev`. → Task 3 test `login_hint is trimmed and lowercased`.
2. A signed-out user follows `verification_uri`, signs in, and lands back on the claim page, not the panel. → Task 4 test `return_to round-trips to the claim page`.
3. The agent re-mints a code while the user still has the old page open: submitting the old page says the code expired and does not count a failure on the new attempt. → Task 4 test `a superseded attempt answers code expired`.
4. A wrong code, then the right code from the re-rendered form: the second submit approves (the first `held` was spent, so the failure page must carry a fresh one). → Task 4 test `wrong code then right code approves`.
5. Garbage on `/token` (unknown `claim_token`, unsigned/foreign-audience `assertion`, missing params) answers `invalid_grant` / `invalid_request`, never 500. → Task 5 test `malformed grants answer 400`.

  ```ts
  export const AGENT_REGISTRATION_TTL_MS = 24 * 60 * 60 * 1000;
  export const AGENT_CODE_TTL_MS = 10 * 60 * 1000;
  export const AGENT_POLL_INTERVAL_MS = 5_000;
  export const AGENT_MAX_CODE_FAILURES = 5;
  export const AGENT_REGS_PER_HOUR = 20;
  export const AGENT_UNCLAIMED_CAP = 10_000;
  export const CLAIM_GRANT = "urn:workos:agent-auth:grant-type:claim";
  export const JWT_BEARER_GRANT = "urn:ietf:params:oauth:grant-type:jwt-bearer";
  export const ASSERTION_AUDIENCE = "bellman:agent-assertion";
  export const AGENT_COUNT_KEY = "agentregs:count";

  export interface AgentAttempt { attempt_token: string; attempt_id: string; user_code: string; expires_at: number; failures: number }
  export interface AgentClaimed { identity: Identity; plan_source: string; plan_key?: string | null; identity_keys: string[] }
  export interface AgentRegistration { registration_id: string; login_hint: string; created_at: number; expires_at: number; last_poll_at: number | null; attempt: AgentAttempt; claimed: AgentClaimed | null }
  export interface AgentGrant extends AgentClaimed { expires_at: number }

  export function emailKey(loginHint: string): string;            // `email:${trim+lowercase}`
  export function newUserCode(): string;                            // 6 digits, crypto.getRandomValues, zero-padded
  export function newAttempt(now: number): AgentAttempt;            // attempt_token randomId(), attempt_id "cla_"+randomId(16), expires now+AGENT_CODE_TTL_MS, failures 0

  export type PollVerdict =
    | { kind: "unknown" } | { kind: "expired" } | { kind: "slow_down" } | { kind: "pending" }
    | { kind: "granted"; registration_id: string; claimed: AgentClaimed };
  export function decidePoll(reg: AgentRegistration | undefined, now: number): PollVerdict;

  export type ApproveVerdict =
    | { kind: "approved" } | { kind: "wrong_code"; left: number } | { kind: "dead" }
    | { kind: "wrong_account" } | { kind: "code_expired" } | { kind: "reg_expired" }
    | { kind: "already" } | { kind: "unknown" };
  export function decideApprove(reg: AgentRegistration | undefined, attemptToken: string, code: string, identityKeys: string[], now: number): ApproveVerdict;

  export type ReissueVerdict = "ok" | "unknown" | "expired" | "claimed" | "mismatch";
  export function decideReissue(reg: AgentRegistration | undefined, email: string, now: number): ReissueVerdict;
  ```
  Decisions are pure: they never mutate `reg`. The store applies the side effects named below.

**Interfaces:**
- Consumes: Task 1 types and decisions; `Admission` from storage.ts.
- Produces on `AuthStorage` (and `AuthDO`, `AuthStore`, `MemoryAuthStore`):
  ```ts
  admitAgentRegistration(claimToken: string, reg: AgentRegistration, ip: string, now: number): Promise<Admission>;
  reissueAgentCode(claimToken: string, email: string, now: number): Promise<{ verdict: ReissueVerdict; reg?: AgentRegistration }>;
  readAgentAttempt(attemptToken: string, now: number): Promise<AgentRegistration | null>;
  approveAgentClaim(attemptToken: string, code: string, claimed: AgentClaimed, now: number): Promise<ApproveVerdict>;
  pollAgentClaim(claimToken: string, now: number): Promise<PollVerdict>;
  getAgentGrant(registrationId: string, now: number): Promise<AgentGrant | null>;
  deleteAgentGrant(registrationId: string): Promise<void>;
  ```
  `Reclaimed` gains `agent: number` (agentreg + agentattempt + agentgrant records deleted). Only `toMatchObject` assertions exist on `Reclaimed`, so no existing test changes.

Keys and side effects (each method is one `ctx.storage.transaction` in `AuthDO`):
- `agentreg:<claim_token>` → `AgentRegistration`. `agentattempt:<attempt_token>` → `{ claim_token, expires_at }`. `agentgrant:<registration_id>` → `AgentGrant`. `agentip:<ip>` → the same bucket shape `admitRegistration` uses for `reg:`. `agentregs:count` → number (absent = 0).
- `admitAgentRegistration`: IP bucket over `AGENT_REGS_PER_HOUR` → `"rate_limited"`; count `>= AGENT_UNCLAIMED_CAP` → `"full"`; else write reg + attempt + bucket, count+1, `"ok"`. `AuthDO` arms the sweep after the transaction.
- `reissueAgentCode`: on `"ok"`, delete the old `agentattempt:`, set `reg.attempt = newAttempt(now)`, write both, return the new reg.
- `readAgentAttempt`: follows `agentattempt:` → `agentreg:`; null if either is missing or the attempt record expired. No writes.
- `approveAgentClaim`: follows the attempt map (missing → `decideApprove(undefined, …)`), then applies the verdict: `wrong_code` → failures+1; `dead` → failures+1 and delete the `agentattempt:`; `approved` → `reg.claimed = claimed`. Other verdicts write nothing.
- `pollAgentClaim`: every verdict except `unknown`/`granted` sets `last_poll_at = now`. `granted` deletes `agentreg:` and its `agentattempt:`, writes `agentgrant:<registration_id>` with `expires_at = now + REFRESH_TOKEN_TTL_MS`, count−1.
- `getAgentGrant`: null when missing or `now > expires_at`.
- `purgeStale` gains three `sweepPage` passes (own cursor keys): `agentreg:` expired → delete it, its attempt, count−1; `agentattempt:` expired → delete; `agentgrant:` expired → delete. Plus `agentip:` buckets whose window passed (counted in `buckets`). `complete` is the AND of every pass.

### Task 5: The two `/token` grants

**Files:**

**Interfaces:**
- Consumes: `pollAgentClaim`, `getAgentGrant`, `deleteAgentGrant` (Task 2); `replanOnRefresh`, `SignInRefused`, `identityFromAccessToken`.
- Produces:
  ```ts
  async function accessTokenBody(config: OAuthConfig, resource: string, identity: Identity, planSource: string):
    Promise<{ access_token: string; token_type: "Bearer"; expires_in: number; scope: string }>;
  ```

Behaviour (D4, D5, D6):
- `grant_type=urn:workos:agent-auth:grant-type:claim`, `claim_token` required (missing → `invalid_request`). Verdicts: `unknown` → `invalid_grant`; `pending` → 400 `{error:"authorization_pending", error_description, status:"pending"}`; `slow_down` → 400 `slow_down`; `expired` → 400 `{error:"expired_token", error_description, status:"expired"}`; `granted` → 200 `{...accessTokenBody(config, config.resource, identity, plan_source), identity_assertion, assertion_expires: ISO}`.
- Assertion: `signJwt({ iss: config.issuer, sub: identity.userId, aud: ASSERTION_AUDIENCE, jti: registration_id }, config.secret, REFRESH_TOKEN_TTL_MS / 1000)`; `assertion_expires` equals the grant's `expires_at`.
