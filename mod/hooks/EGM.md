# mod/hooks

## Overview

What Claude Code loads for `bellman-mod`. `hooks.json` names one module,
`register.mjs`, and `register.mjs` is a generated esbuild bundle of
[`../src/`](../src/EGM.md) plus the shared `src/mod/` and
`src/door-protocol.ts` it imports. Read and edit the sources, never the
bundle. It is committed because the plugin runs it.

## Interface

- `hooks.json`: `{"modules": ["./register.mjs"]}` [mod/hooks/hooks.json:modules]
- `register.mjs`: the bundle of `mod/src/register.tsx`, exporting what that
  entry exports (`register` and the kit-test re-exports); see
  [`../src/EGM.md`](../src/EGM.md) [scripts/build-mod.ts:buildMod]

## Invariants

- Generated by `npm run build:mod` (`scripts/build-mod.ts` `buildMod`):
  entry `mod/src/register.tsx`, ESM, platform neutral, target es2022, JSX
  factory `h`, unminified [scripts/build-mod.ts:buildMod]
- `claude-code` is the only external import; everything else is bundled in,
  and `tsconfigRaw: {}` means `mod/tsconfig.json` is not read
  [scripts/build-mod.ts:external]
  [tests/plugin.test.ts:the mod's shape]
- `npm run build:plugin` runs `buildMod()` too, so every release PR rebuilds
  this bundle [scripts/build-plugin.ts:(top-level CLI)]; CI and `publish.yml` fail a
  version bump with a stale bundle [CLAUDE.md:mod/hooks/register.mjs follows the same rule]

## Side Effects

- None at build time beyond the file itself: `buildMod` writes
  `mod/hooks/register.mjs` [scripts/build-mod.ts:build]
- At run time, those of [`../src/`](../src/EGM.md)

## Verification

- Run: `npm run build:mod`, then `npm run test:mod`
