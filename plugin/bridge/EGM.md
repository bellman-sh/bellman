# plugin/bridge

## Overview

The five Node bundles the `bellman` Claude Code plugin runs, plus the license
notices of what they bundle. All of it is generated by `npm run build:plugin`
(`scripts/build-plugin.ts`) and committed, because the plugin runs these files
and never `src/`. Read and edit the sources; never the bundles.

## Interface

| Bundle | Source | Run by |
| --- | --- | --- |
| `channel.mjs` | `src/channel.ts` | `plugin/.mcp.json` as the `bellman` MCP server |
| `join-hook.mjs` | `src/join-hook.ts` | `SessionStart` hook |
| `stop-hook.mjs` | `src/stop-hook.ts` | `Stop` hook |
| `status-hook.mjs` | `src/status-hook.ts` | `UserPromptSubmit` and `Notification` hooks |
| `monitor.mjs` | `src/client/monitor.ts` | `plugin.json` `experimental.monitors` as `bellman-events` |

## Invariants

- Built with esbuild for platform node, ESM, target node22, minified
  [scripts/build-plugin.ts:(top-level CLI)]
- Each bundle starts with a shebang and a `createRequire` banner, because
  bundled CommonJS calls `require()` for Node built-ins
  [scripts/build-plugin.ts:banner] [plugin/bridge/*.mjs:header]
- `package.json`'s version is inlined as `BELLMAN_BUNDLE_VERSION`, since the
  bundle has no `package.json` to read; the spawned `channel.mjs` reports it as
  `serverInfo.version` [scripts/build-plugin.ts:define.BELLMAN_BUNDLE_VERSION]
  [tests/plugin.test.ts:reports package.json's version]
- Notices are keyed `name@version` and sorted by code point, so the output is
  deterministic; they must include the MCP SDK (`@modelcontextprotocol/sdk@` and its `fast-uri@` in bundles built
  before #571, the v2 `@modelcontextprotocol/core@`, `client@` and `server@` after), `yaml@` and `zod@` [scripts/build-plugin.ts:notices]
  [tests/plugin.test.ts:carries Bellman's license and the notices of every package it bundles]
- Every file `.mcp.json`, `hooks.json` and `plugin.json` name exists here
  [tests/plugin.test.ts:runs only files that exist under plugin/]
- A bridge change between releases leaves these files alone; every release PR
  rebuilds them, and a version bump without a rebuild fails CI
  [CLAUDE.md:plugin/bridge/*.mjs are generated by npm run build:plugin]
- `join-hook.mjs` always exits 0 [plugin/bridge/join-hook.mjs:tail]

## Side Effects

- Building writes the four bundles and `THIRD-PARTY-NOTICES.txt`, reads
  `node_modules` package and license files, and also rebuilds
  `mod/hooks/register.mjs` through `buildMod()` [scripts/build-plugin.ts:build]
- At run time, the effects of their sources under `src/` (not documented here)

## Verification

- Run: `npm run build:plugin`, then `npx vitest run tests/plugin.test.ts`
