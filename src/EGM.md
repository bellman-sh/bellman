# src

## Overview

Everything Bellman runs, in one package with two build targets. The server half answers MCP at `/mcp`, the
room socket at `/ws`, and the HTTP routes beside them; it runs on Cloudflare Workers (`workerd/`: the entry and six Durable
Object classes) in production and on Node (`index.ts`, `app.ts`) with an in-memory store for tests and
`npm start`. The client half, in `client/`, is what a Claude Code session runs locally: the stdio bridge, the local bus, the
door socket the mod reads, the hooks, browser sign-in and the `bellman` CLI.

Between them sits the storage boundary, in `storage/`. `BellmanStore` (`storage/store.ts`) is the one interface every
tool and route writes through; `MemoryStore` (`storage/memory-store.ts`) implements it in memory and `DurableObjectStore` (`workerd/store-do.ts`) forwards each
call to a `SessionDO` per room, the singleton `RegistryDO`, or an `AuditDO` per org. Room operations shared by
the MCP tools and the HTTP routes live in `rooms.ts`, so a transport only translates a `RoomResult`. Most other
files at this level are runtime-free rule modules (manifest validation, surface placement, heartbeat, decisions,
retention, audit chain, send limits) kept free of `cloudflare:workers` so the Node build, the Workers build and
vitest can all import them.

`tsconfig.json` and `tsconfig.test.json` exclude `workerd/` from the Node build: every file there imports
`cloudflare:workers`, uses Workers-only types, or imports a file that does, and `tsconfig.worker.json` checks
them instead. `ui/assets.ts` is generated by `npm run build:ui` and gitignored.

## Interface

### Subdirectories

- [a2a](./a2a/EGM.md) - `POST /a2a`: A2A v1.0 JSON-RPC from an outside agent that holds no seat, answered by a
  public, open room (ADR 0033).
- [billing](./billing/EGM.md) - Stripe: the webhook, and the ledger of who has paid for what.
- [http](./http/EGM.md) - the plain-HTTP routes beside `/mcp`: the control panel's room, preset, org, audit and
  account routes, and the credential-free public room reads.
- [mod](./mod/EGM.md) - the runtime-free logic of `bellman-mod`, the Claude Code mod, vitest-tested and bundled
  into `mod/hooks/register.mjs`.
- [oauth](./oauth/EGM.md) - the authorization server: tokens, storage, providers, routes.
- [scim](./scim/EGM.md) - SCIM v2 provisioning of org members, where deprovision ends sign-in (ADR 0029).
- [storage](./storage/EGM.md) - `BellmanStore`, `MemoryStore`, the write rules both stores apply, and the
  storage layout helpers.
- [tools](./tools/EGM.md) - one file per MCP tool, plus `kit.ts` for the result shape and zod input shapes they
  share.
- [client](./client/EGM.md) - what a Claude Code session runs locally: the bridge, the local bus, the door,
  the inbox, the hooks, sign-in and the `bellman` CLI.
- [workerd](./workerd/EGM.md) - the Workers entry and the six Durable Object classes: everything the Node
  program cannot compile.
- [ui](./ui/EGM.md) - the one `ui://` resource and the `_meta` a tool carries to be rendered through it.

### Entries and composition

- The Workers entry, `workerd/worker.ts`, is in [workerd](./workerd/EGM.md).
- `[server.ts:buildServer]` `(identity, store, blobs, features: {hostedSeat, mailReport?, upgrade?}) => McpServer`:
  a new server per request, bound to one caller, registering the 14 tools from `tools/` and the app resource.
  `SERVER_NAME` is `"bellman-mcp-server"`, `SERVER_VERSION` `"0.7.0"`.
- `[server-card.ts:serverCard]` the static MCP Server Card at `SERVER_CARD_PATH` (`/mcp/server-card`), with
  `SERVER_CARD_CORS`.
- `[app.ts:createApp]` `(store, blobs, {hostedSeat})`: the Node Express app mounting the same route modules,
  `/a2a`, `GET /healthz`, `POST /__fake-model` and `POST /mcp`. `[index.ts]` wires `MemoryStore`,
  `MemoryBlobStore` and `MemoryHost` into it and listens on `PORT` (default 3900).

### Storage boundary

- The storage boundary is in [storage](./storage/EGM.md).

### Room operations and wire shapes

- `[rooms.ts]` the operations both transports call, each returning `RoomResult<T>` (`succeed`/`refuse` with a
  `RoomFailure` of `not_found | closed | frozen | forbidden | conflict | invalid | rate_limited | stale | too_large |
  over_quota | paused`): `gateSeat`, `leaveRoom`, `issueInvite`, `revokeInvite`, `admitSend`, `writeSurface`,
  `writeSurfaceBatch`, `resolveSurfaceWrite`, `checkProposal`, `evictMember`, `banAsker`, `fileRoomReport`, `namePublicRoom`,
  `liveRooms` (`ROOMS_LIMIT = 50`), `readSurfaceWindow`, `searchSurface`, `searchLog`, and `audit`.
- `[rooms.ts:activeMembers]` membership as stored; `[rooms.ts:seatedMembers]` the presence-derived roster a
  capacity check counts.
- `[types.ts]` the domain model: `Session`, `Member`, `SessionEvent`, `EventType` (23 types), `SEND_KINDS` (the
  8 a member may write), `RoomManifest`, `Identity`, `Plan`, `Org`, `SurfaceRow` and `SurfaceKind`.
- `[projections.ts]` runtime-free projections from stored rows to wire objects, shared by tools and routes:
  `untrusted`, `publicMember`, `roomPreview`, `roomSummary`, `surfaceItem`, `surfaceIndex`, `ROOM_TAIL = 100`,
  and `decisionShown` (a decision as `bellman_decide read` and `GET /rooms/:id/decisions` show it) with
  `decisionMembers` (the room's members plus each departed seat a decision names, read by id).
- `[public-event.ts:publicEvent]` the one event shape both `bellman_sync` and `/ws` send;
  `publicReadEvent` and `readableEvents` filter it for public reads and for `read_context`;
  `[public-event.ts:accountAliases]` turns a decision snapshot's accounts into `a1`, `a2`, ... aliases.
- `[attention.ts:ATTENTION]` every `EventType` as `interrupt` or `ambient`; `[presence.ts:presenceOf]`
  (`present | stale | departed`, `STALE_AFTER_MS` = 10 min).

### Rule modules

- Members: `[members.ts]` the roster rules both stores apply (`isActiveMember`, `lastSeen`, `seatInOrder`,
  `seatVictims`, `markRemoved`, `creditReport`, `noteAppend`, `clearSilence`, `asked`) and the hosted seat's ids
  (`HOST_MEMBER_ID`, `HOST_USER_ID`, `isHostMember`).
- Manifests and roles: `[manifest.ts:resolveManifest]` (cited presets `pair`, `swarm`, `review`, `social`,
  `topic`, or an authored manifest; throws `ManifestError`), `VERBS`, `[presets.ts:checkPreset]`,
  `[roles.ts:denyVerb]`, `verbsOfRole`, `mustReport`.
- Names and codes: `[codes.ts:renderJoinCode]` (`BELL-XXXX-XX-ROLE`), `generateSessionId` (`qs_`),
  `generateConnectToken` (`qct_`), `publicRoomUrl`; `[handles.ts:checkHandle]`;
  `[public-names.ts:claimName]`, `holdsName`; `[member-names.ts:publicNames]` (`member N`, `host`).
- Sends: `[payload.ts]` (`MAX_PAYLOAD_CHARS`, `MAX_PAYLOAD_DEPTH`), `[send-limit.ts:admitAt]`,
  `[client/result-data.ts:resultData]`.
- Surface: `[surface.ts:normalizeSurfaceWrite]`, `normalizeSurfaceBatch`, `applySurfaceWrite`, `withPlacement`,
  `SURFACE_KINDS`; `[frames.ts:readWindow]`, `placeSurfaceWrite`, `parseWindow`, `MAX_FRAMES = 100`,
  `SURFACE_PAGE = 64`; `[search.ts:searchCards]`, `searchMessages`.
- Room lifecycle: `[heartbeat.ts:tickPlan]`, `nextTickAt`, `snapshotOf`; `[housekeeping.ts:dueFindings]`;
  `[retention.ts:purgeDueAt]`, `sweepDueAt`, `unnamedObjects`; `[action-state.ts:actionStates]`;
  `[proposal.ts:decideApproval]`.
- Decisions (ADR 0040): `[decision.ts:evaluate]` the rule engine (closes a decision `passed`, or `failed` as
  `vetoed`, `blocked`, `rejected` or `no_quorum`, once the worst case for the seats yet to vote decides it; never
  for `single`), `applyVote`, `decisionsOf`, `tally`, `ruleOf`, `decisionTtlMs`; the quotas `decideOpenQuota`,
  `noteDecisions` (the `OpenDecisions` book), `dueToExpire`; `removalEvents` (what a leave or eviction writes into
  unclosed decisions); `decisionAudit` (the org's rows per decision event); `decisionsAwaiting` (`bellman_sync`'s
  open decisions); `decisionPageOf`, `decisionOwning` (the read page and its index).
- Outside callers: `[outside.ts:askRoom]`, `answerQuestion`, `cancelOutsideTask`, and the pure `decideAsk`,
  `decideAnswer`, `decideCancel`, `endTask`.
- Identity and plans: `[auth.ts:resolveIdentity]`, `ENTITLEMENTS`, `entitlementsFor`, `upgradeHint`,
  `keyedPlan`; `[bans.ts]` (`BANNED`, `newBanId`, `isBanId`); `[suspension.ts:SuspensionCache]`.
- Orgs and audit: `[orgs.ts:joinRefusal]`, `parsePolicyPatch`, `ownsByForm`, `scimSeatKey`;
  `[audit.ts:auditRows]`, `auditWhere`, `auditRefusal`; `[audit-sink.ts:chainHash]`, `chainWalk`,
  `deliverBatch`, `nextSinkState`; `[grant-audit.ts:grantAuditEntries]`; `[reports.ts]` (`REPORT_REASONS`,
  `reachesCreator`, `reportMailer`); `[invite-mail.ts:inviteLink]`, `verifyInviteLink`, `inviteMailer`.

- Shared small modules: `[client/version.ts:VERSION]`, `compareVersions`; `[keepalive.ts]` (`PING`, `PONG`);
  `[upgrade.ts:wantsWebSocket]`, `UPGRADE_REQUIRED`; `[rpc-error.ts:reviving]`.

### Hosted seat

- `[host.ts:handleWake]` / `runWake` one wake of the hosted seat end to end: admission (`admit`), prompt
  (`questionPrompt`, `answerPrompt`, `outsidePrompt`), one Messages API call (`callMessages`), the write, and
  a retry delay. `[host.ts:HostDriver]` is the runtime contract; `HOST_MODELS` maps `haiku`, `sonnet`, `opus`
  to model ids; `hostedSeatFor` reads the `BELLMAN_HOSTED_SEAT` switch and allowlist.
- `[host-memory.ts:MemoryHost]` the Node and test driver; `nodeModel` picks the model endpoint.

### Blobs

- `[blobs.ts:BlobStore]` `put`, `head`, `get`, `delete`, `list`, `deleteAll`; `[blobs.ts:MemoryBlobStore]`;
  helpers `blobKey`, `newBlobId`, `storedType`, `sanitizeName`, `exactLength`, `MAX_BLOB_BYTES` (25 MB).

## Invariants

The store's own invariants (async methods, read and register in one turn, single-unit appends, seat claims,
decisions) are in [storage](./storage/EGM.md).

### Across objects

- No transaction spans two Durable Objects. Cross-object writes go through the outbox
  (`[storage/outbox.ts:enqueueRows]`): rows are written in the mutation's own transaction under `ob:`, delivered FIFO
  with backoff capped at 300 s (`[storage/outbox.ts:backoffMs]`), never dropped, and a failing head blocks the rows behind
  it (`[storage/outbox.ts:drain]`). `[workerd/session-do.ts:SessionDO.#deliver]` throws on an unknown kind so the row stays queued.

### Untrusted content and trust boundaries

- Peer content crosses wrapped: `[projections.ts:untrusted]` returns `{trust: "untrusted", origin, data}`;
  `[client/inbox.ts:renderEvent]` heads each event "UNTRUSTED PEER CONTENT" and `[client/inbox.ts:safeJson]` replaces every `<`
  with the JSON escape `\u003c` so a payload cannot close the `<channel>` tag; `[client/inbox.ts:safeMeta]` restricts channel meta to
  `[A-Za-z0-9_.:@+-]` and 80 characters.
- `[public-event.ts:publicEvent]` never sends `fromUserId`, and replaces a `decision_opened` snapshot's account ids
  with `accountAliases`; `[projections.ts:decisionShown]` does the same and wraps proposals and vote reasons with
  `untrusted()`; `[public-event.ts:publicReadEvent]` drops
  `brief_update` and cuts `member_joined` to id, label and role.
- `[host.ts:escapeText]` escapes untrusted text before it enters a prompt, `[host.ts:HOST_RULES]` puts Bellman's
  rules above the creator's instructions, and `[host.ts:answerPrompt]` names senders by public number, never
  label.
- `[auth.ts:resolveIdentity]` treats a set `BELLMAN_KEYS` as authoritative and fails closed on malformed JSON;
  `[workerd/worker.ts:resolveCaller]` calls it only when `BELLMAN_KEYS` is set, because without a table it falls back to
  dev keys; `[workerd/worker.ts:unconfigured]` answers 503 when neither keys nor OAuth is configured.

### Limits

- Room members: `ROOM_MEMBER_CEILING = 5000`, 2 for `pair` `[manifest.ts:capacityOf]`. Sends: 30 per rolling minute
  per member, 6 per stranger `[send-limit.ts:SEND_LIMIT]`. Payloads: 20,000 characters, 64 levels
  `[payload.ts:MAX_PAYLOAD_CHARS]`.
- Surface: 1,000 items `[surface.ts:MAX_SURFACE_ITEMS]` (enforced in `[rooms.ts:checkAgainstFacts]` as a
  read-then-write courtesy bound), 100 frames `[frames.ts:MAX_FRAMES]`, batches of 1 to 100
  `[surface.ts:MAX_SURFACE_BATCH]`, bodies of 8,000 characters. Blobs: 25 MB `[blobs.ts:MAX_BLOB_BYTES]`; image
  types are kept only when `sniffImageType` agrees `[blobs.ts:storedType]`.
- Reports: 10 per rolling 24 h, folded per target, resolved reports deleted after 180 days
  `[reports.ts:REPORTS_PER_DAY]`, `[reports.ts:REPORT_RETENTION_MS]`. Outside tasks: 3 open per caller, 7 days
  idle, 10 min before the seat hands off, 20 seat answers per UTC day `[outside.ts:MAX_OPEN_OUTSIDE_TASKS]`.
- Hosted seat: 8 wakes per hour `[host.ts:WAKES_PER_HOUR]`, 3 replies per question
  `[host.ts:REPLIES_PER_QUESTION]`, 4 attempts with 60 s, 300 s and 900 s retries `[host.ts:RETRY_MS]`, model
  calls aborted at 30 s `[host.ts:MODEL_TIMEOUT_MS]`.
- Action requests stay answerable 30 minutes, topic-room proposals 7 days `[action-state.ts:ACTION_REQUEST_TTL_MS]`;
  the first response wins and only `approved === true` counts as an approval `[action-state.ts:verdictOf]`.
- Decisions: 20 open per room, 3 open per opening seat, 5 revisions of one seat's vote on one decision
  `[decision.ts:MAX_OPEN_DECISIONS]`, `[decision.ts:MAX_OPEN_PER_SEAT]`, `[decision.ts:MAX_REVISIONS]`; an expiry
  from 5 minutes to 7 days `[decision.ts:MIN_DECISION_TTL_MS]`; a page of 50 by default and 100 at most
  `[decision.ts:DECISION_PAGE]`. Only a binding vote (`dash_session`, or an `action_response` with
  `human_approved: true`) counts, one per account `[decision.ts:capacityOfVote]`.

## Side Effects

- Outbound HTTP: the Anthropic Messages API (`https://api.anthropic.com/v1/messages`, or `MODEL_URL`)
  `[host.ts:callMessages]`; an org's SIEM sink, HMAC-signed, https only, redirects not followed
  `[audit-sink.ts:deliverBatch]`; email through the `SEND_EMAIL` and `INVITE_EMAIL` bindings
  `[reports.ts:reportMailer]`, `[invite-mail.ts:inviteMailer]`.
- Node server: listens on `PORT` (3900) and runs `sweep`, `tick` and `housekeep` every 60 s `[index.ts]`.
- Environment read. Server: `BELLMAN_KEYS`, `BELLMAN_HOSTED_SEAT`, `BELLMAN_HOSTED_SEAT_USERS`,
  `ANTHROPIC_API_KEY`, `MODEL_URL`, `PORT`, plus the secrets in `[workerd/worker.ts:WorkerEnv]`. Client: `BELLMAN_KEY`,
  `BELLMAN_URL`, `BELLMAN_DELIVERY`, `BELLMAN_INSTALL`, `BELLMAN_BUS`, `BELLMAN_NO_BROWSER`, `BELLMAN_JOIN_CODE`,
  `BELLMAN_UPLOAD_ROOT`, `BELLMAN_INBOX_ROOT`, `BELLMAN_BUS_ROOT`, `BELLMAN_DOOR_ROOT`,
  `BELLMAN_HOOK_WAIT_SECONDS`, `XDG_CONFIG_HOME`.

## Verification

- Run: `npm test` (vitest; runs `build:ui` first). `tests/helpers/store-contract.ts` is the conformance suite
  every `BellmanStore` must pass, run against `MemoryStore` here.
- Run: `npm run typecheck:worker` and `npm run test:worker` for `workerd/` (see [workerd](./workerd/EGM.md)).
- Run: `npm run verify` before every commit (both typechecks, the build, `npm test`, `test:worker`, `test:mod`).
- A new tool also means editing `extension/manifest.json` and running `npm run docs:gen`
  (`tests/extension.test.ts`, `tests/docs-reference.test.ts`).
