# src

## Overview

Everything Bellman runs, in one package with two build targets. The server half answers MCP at `/mcp`, the
room socket at `/ws`, and the HTTP routes beside them; it runs on Cloudflare Workers (`worker.ts`, five Durable
Object classes) in production and on Node (`index.ts`, `app.ts`) with an in-memory store for tests and
`npm start`. The client half is what a Claude Code session runs locally: the stdio bridge (`bridge.ts`,
started by `channel.ts`), the local bus that lets every bridge on a machine share one upstream connection per
room (`bus.ts`, `bus-link.ts`, `room-socket.ts`), the door socket the mod reads (`door.ts`), the Stop, status
and join hooks, browser sign-in, and the `bellman` CLI.

Between them sits the storage boundary. `BellmanStore` (`store.ts`) is the one interface every tool and route
writes through; `MemoryStore` implements it in memory and `DurableObjectStore` (`store-do.ts`) forwards each
call to a `SessionDO` per room, the singleton `RegistryDO`, or an `AuditDO` per org. Room operations shared by
the MCP tools and the HTTP routes live in `rooms.ts`, so a transport only translates a `RoomResult`. Most other
files at this level are runtime-free rule modules (manifest validation, surface placement, heartbeat, decisions,
retention, audit chain, send limits) kept free of `cloudflare:workers` so the Node build, the Workers build and
vitest can all import them.

`tsconfig.json` excludes `worker.ts`, `store-do.ts`, `host-do.ts` and `blobs-r2.ts` (plus `oauth/store.ts`)
from the Node build: they import `cloudflare:workers` or use Workers-only stream types, and
`tsconfig.worker.json` checks them instead. `ui/assets.ts` is generated by `npm run build:ui` and gitignored.

## Interface

### Subdirectories

- [a2a](./a2a/EGM.md) - `POST /a2a`: A2A v1.0 JSON-RPC from an outside agent that holds no seat, answered by a
  public, open room (ADR 0033).
- [billing](./billing/EGM.md) - Stripe: the webhook, and the ledger of who has paid for what.
- [http](./http/EGM.md) - the plain-HTTP routes beside `/mcp`: the control panel's room, preset, org, audit and
  account routes, and the credential-free public room reads.
- [mod](./mod/EGM.md) - the runtime-free logic of `bellman-mod`, the Claude Code mod, vitest-tested and bundled
  into `mod/hooks/register.mjs`.
- [oauth](./oauth/EGM.md) - the authorization server: tokens, storage, providers, routes.
- [scim](./scim/EGM.md) - SCIM v2 provisioning of org members, where deprovision ends sign-in (ADR 0029).
- [tools](./tools/EGM.md) - one file per MCP tool, plus `kit.ts` for the result shape and zod input shapes they
  share.
- [ui](./ui/EGM.md) - the one `ui://` resource and the `_meta` a tool carries to be rendered through it.

### Entries and composition

- `[server.ts:buildServer]` `(identity, store, blobs, features: {hostedSeat, mailReport?, upgrade?}) => McpServer`:
  a new server per request, bound to one caller, registering the 14 tools from `tools/` and the app resource.
  `SERVER_NAME` is `"bellman-mcp-server"`, `SERVER_VERSION` `"0.7.0"`.
- `[server-card.ts:serverCard]` the static MCP Server Card at `SERVER_CARD_PATH` (`/mcp/server-card`), with
  `SERVER_CARD_CORS`.
- `[worker.ts:fetch]` the Workers entry. Dispatch order: `/stripe/webhook`; `/rooms[/*]` (moderation routes, then
  room routes); `/public[/*]`; `/presets`, `/scim/v2`, `/audit`, `/org`, `/me/rooms`, `/account/handle`,
  `/account/bans`, `/operator/(stats|accounts|rooms)` and `/operator/rooms/:id`; `GET /.well-known/agent-card.json`; the server card; OAuth
  routes; `GET /healthz`; `GET /ws`; A2A paths; `POST /mcp`. Anything else is 404.
- `[worker.ts]` re-exports the Durable Object classes `SessionDO`, `RegistryDO`, `AuditDO` (from `store-do.ts`),
  `AuthDO` (from `oauth/store.ts`) and `HostDO` (from `host-do.ts`). `[worker.ts:WorkerEnv]` extends
  `BellmanEnv` with `AUTH`, `BLOBS`, the mail bindings, and the OAuth, operator, panel-origin and Stripe secrets.
- `[worker.ts:resolveCaller]` identity from an OAuth access token minted for the named resource (`/mcp` or
  `/a2a`), else `resolveIdentity` over `BELLMAN_KEYS`.
- `[app.ts:createApp]` `(store, blobs, {hostedSeat})`: the Node Express app mounting the same route modules,
  `/a2a`, `GET /healthz`, `POST /__fake-model` and `POST /mcp`. `[index.ts]` wires `MemoryStore`,
  `MemoryBlobStore` and `MemoryHost` into it and listens on `PORT` (default 3900).

### Client side (local, Node)

- `[channel.ts]` the stdio MCP entry Claude Code spawns: reads the environment, builds the bridge, opens the door,
  starts an optional join, and shuts down on SIGTERM, SIGINT or stdin close.
- `[bridge.ts:createBridge]` the local MCP server: relays the remote tools and resources, adds `bellman_whoami`,
  `bellman_upload` and, outside channel delivery, `bellman_wait`; learns memberships from tool results
  (`observe`) and delivers peer events by `Delivery` = `channel | hook | queue`. Exposes the door's reads and
  writes (`readEvents`, `readRooms`, `readSurface`, `decline`, `writeSurface`, `setStatus`, `join`).
- `[inbox.ts]` the on-disk event queue per Claude Code pid (`enqueue`, `drain`, `discardThrough`), membership
  files, and `renderEvent`/`renderBatch`, which frame peer content as untrusted.
- `[bus.ts:openBus]` one coordinator per machine and identity serving the other bridges over a Unix socket
  (NDJSON); `[bus.ts:RoomWindow]` the coordinator's contiguous window of recent events.
- `[bus-link.ts:createBusLink]` links a bridge's watches to the bus and room sockets and hands a member back to
  polling through `onFallback`. `[room-socket.ts:openRoomSocket]` one upstream WebSocket to `/ws` per room,
  degrading to an injected `poll`.
- `[door.ts:startDoor]` an HTTP server on a Unix socket per bridge: `GET /status`, `GET /rooms`,
  `GET /rooms/<id>/events`, `GET /rooms/<id>/surface`, and the writes `POST /rooms/<id>/decline`,
  `POST /seats/status`, `PUT`/`DELETE /rooms/<id>/surface/<key>`. `[door-protocol.ts]` the runtime-free shapes
  shared with the mod (`DOOR_VERSION = 1`, `cleanText`, `cleanBlock`, `eventLine`).
- Hooks: `[stop-hook.ts]` (drains the inbox, exits 2 to keep the turn going), `[status-hook.ts:statusFor]`
  (`working` / `needs_you`), `[join-hook.ts:joinLine]`.
- `[signin.ts:connectSignedIn]` browser OAuth with PKCE on a loopback callback (`CALLBACK_PORTS` 51004-51008);
  `[signin.ts:signedInAs]`. `[credentials.ts]` the credential file (`readServer`, `writeServer`,
  `acquireLock`, `busCredentials`).
- `[cli.ts:run]` the `bellman` command: `help`, `version`, `feature-request`, `update [--check]`, `doctor`.
  `[doctor.ts:diagnose]` read-only checks with a fix command for each finding.
- Shared small modules: `[version.ts:VERSION]`, `compareVersions`; `[keepalive.ts]` (`PING`, `PONG`);
  `[upgrade.ts:wantsWebSocket]`, `UPGRADE_REQUIRED`; `[rpc-error.ts:reviving]`.

## Invariants

### The store

- Every `BellmanStore` method is async `[store.ts:BellmanStore]`; reads return detached copies
  (`structuredClone` in `[store.ts:detach]`, applied to `MemoryStore` reads and writes).
- Read and register in one turn. `[store-do.ts:SessionDO.waitForEvents]` awaits the event read, then pushes its
  waiter onto `this.waiters` synchronously; `[store.ts:MemoryStore.waitForEvents]` is not `async`, so its read
  and registration share one synchronous turn. `[store-do.ts:SessionDO.fetch]` (the `/ws` upgrade) does every
  storage read first and then serializes the attachment, accepts the socket and sends the replay with no await
  between.
- `[store-do.ts:SessionDO.fetch]` rechecks `readsClosed` itself (409) although the Worker already asked
  `membersOf` (#133), drops removed member ids (403 when none remain, #113), and refuses with 410 when more than
  `REPLAY_LIMIT` (1,000) events were missed, so the client catches up through `bellman_sync`.
- The room socket is receive-only: `[store-do.ts:SessionDO.webSocketMessage]` closes on any client frame with
  1003. `[worker.ts:fetch]` builds a fresh `Request` for the object carrying only the validated cursor, the
  upgrade header and `x-bellman-members` from `membersOf`; nothing from the caller's request is forwarded.
- A seat is claimed in one operation. `[store-do.ts:SessionDO.seatMember]` and `[store.ts:MemoryStore.seatMember]`
  refuse in the order not_found, closed, frozen, banned, full (a banned account never learns the room is full),
  reclaim stale seats only when that frees enough (`[store.ts:seatVictims]` returns `null` rather than reaping
  partly), seat the joiner, and retire temporary codes when the room fills, all in one transaction or one
  synchronous stretch. Permanent codes stay (ADR 0020).
- A member is removed only by an authorized call: `[store.ts:RemovalRequest]` carries `byUserId`, and
  `removeMember` refuses `forbidden` when it is not the creator; `[rooms.ts:evictMember]` checks the creator before
  the target lookup and refuses self-eviction. `[store.ts:markRemoved]` writes `leftAt` and `removedAtCursor`
  together and never moves an existing cut.
- Appends are single-unit: `[store-do.ts:SessionDO.nextCursor]` reads the cursor inside the caller's transaction so
  two appends cannot take one `e:` key (#120); `appendEventOnce`, `appendSurface(s)`, `approveProposal` and
  `appendHostEvent` check the idempotency key before the frozen check, and a refusal writes nothing, the key
  record included.
- A decision is decided in the transaction that writes it: `[store-do.ts:SessionDO.openDecision]` checks the quotas
  (`decideOpenQuota`) after the idempotency key, snapshots the electorate, and writes the `expired` close of every
  decision past its deadline after its own events; `castVote` decides through `applyVote` from the decision read in
  that transaction, so no vote lands after a closing event. `[store-do.ts:SessionDO.#writeDecision]` keeps the
  `openDecisions` book and queues each event's org rows (`decisionAudit`) through the outbox in the same put.
- A removal that records a member out also voids that seat's votes on every unclosed decision and writes the close
  that leaves due (`[decision.ts:removalEvents]`), after the departure and in the same transaction
  (`[store-do.ts:SessionDO.removeMember]`); a removal never passes a decision, and a rejoin restores neither the
  seat nor its vote (`[decision.ts:applyVote]`). A `SessionDO` record whose decisions opened before the book existed has no
  book, so those decisions are not voided.
- A surface batch is all or nothing at consecutive cursors (`[store.ts:placeSurfaceBatch]`, decided in memory
  before either store writes); frame writes through `appendEvent` throw `FRAME_WRITE_PATH`.
- Presence is derived, never stored: `[presence.ts:presenceOf]` reads `leftAt`, `lastSeenAt` and live sockets;
  `[heartbeat.ts:snapshotOf]` must carry no `present`, `status`, `alive` or `healthy` key. `activeMembers` and
  `seatedMembers` in `[rooms.ts]` are two readings and stay separate.
- `[store.ts:isAbandoned]` closes a room only past 90 days of no person seen and only when no active member holds a
  socket; `[store-do.ts:SessionDO.#closeIfAbandoned]` stamps `lastSeenAt` instead when a socket vouches.

### Across objects

- No transaction spans two Durable Objects. Cross-object writes go through the outbox
  (`[outbox.ts:enqueueRows]`): rows are written in the mutation's own transaction under `ob:`, delivered FIFO
  with backoff capped at 300 s (`[outbox.ts:backoffMs]`), never dropped, and a failing head blocks the rows behind
  it (`[outbox.ts:drain]`). `[store-do.ts:SessionDO.#deliver]` throws on an unknown kind so the row stays queued.
- `[store-do.ts:DurableObjectStore.createSession]` writes the room first and the registry indexes (`us`, `um`,
  `uo`) after, with no transaction across them; `[store-do.ts:DurableObjectStore.writeIndex]` logs a failed
  index write rather than throwing, and nothing rebuilds a lost `us`, `um` or `uo` row. The operator's room index
  row is written in the same put as the creator's `us:` row (`[store-do.ts:RegistryDO.indexSession]`); a room
  missing from it is restored by `backfillRoomIndex`, and the purge removes it (`dropRoomIndex`). Join codes reach
  the registry through the room's outbox, not the facade.
- `[store-do.ts:DurableObjectStore.getSessionByJoinCode]` treats the registry row as a hint: the room must be open,
  still hold the code, and `codeIsLive` must pass. The public-name index works the same way: claims are
  compare-and-set (`[store-do.ts:RegistryDO.claimPublicName]`) and `[public-names.ts:holdsName]` checks the room
  record.
- `[store-do.ts:DurableObjectStore]` neither retries an RPC nor falls back when a stub lacks a method.
- `[store-do.ts:AuditDO.append]` dedupes by intent id in the same `transactionSync` as the insert, so outbox
  redelivery files one row; each row's `hash` chains to the previous (`[audit-sink.ts:chainHash]`).

### Untrusted content and trust boundaries

- Peer content crosses wrapped: `[projections.ts:untrusted]` returns `{trust: "untrusted", origin, data}`;
  `[inbox.ts:renderEvent]` heads each event "UNTRUSTED PEER CONTENT" and `[inbox.ts:safeJson]` replaces every `<`
  with the JSON escape `\u003c` so a payload cannot close the `<channel>` tag; `[inbox.ts:safeMeta]` restricts channel meta to
  `[A-Za-z0-9_.:@+-]` and 80 characters.
- `[bridge.ts:createBridge]` never declares the `claude/channel/permission` capability, so a peer cannot approve
  tool use in a session; `[bridge.ts:CHANNEL_INSTRUCTIONS]`, `HOOK_INSTRUCTIONS` and `QUEUE_INSTRUCTIONS` each
  tell the agent an `action_request` needs its human's approval.
- `[public-event.ts:publicEvent]` never sends `fromUserId`, and replaces a `decision_opened` snapshot's account ids
  with `accountAliases`; `[projections.ts:decisionShown]` does the same and wraps proposals and vote reasons with
  `untrusted()`; `[public-event.ts:publicReadEvent]` drops
  `brief_update` and cuts `member_joined` to id, label and role.
- `[host.ts:escapeText]` escapes untrusted text before it enters a prompt, `[host.ts:HOST_RULES]` puts Bellman's
  rules above the creator's instructions, and `[host.ts:answerPrompt]` names senders by public number, never
  label.
- `[door-protocol.ts:cleanText]` strips escape sequences, controls and bidi characters before the mod draws a
  peer string; `[door-protocol.ts:lineOf]` reads an `action_response` from `approved` alone.
- `[auth.ts:resolveIdentity]` treats a set `BELLMAN_KEYS` as authoritative and fails closed on malformed JSON;
  `[worker.ts:resolveCaller]` calls it only when `BELLMAN_KEYS` is set, because without a table it falls back to
  dev keys; `[worker.ts:unconfigured]` answers 503 when neither keys nor OAuth is configured.
- `[worker.ts:routeGate]` refuses a suspended caller with 403 before the room, preset, audit, org and account
  modules; `/public` and `/scim/v2` are not gated there.

### Limits

- Room members: `ROOM_MEMBER_CEILING = 5000`, 2 for `pair` `[store.ts:capacityOf]`. Sends: 30 per rolling minute
  per member, 6 per stranger `[send-limit.ts:SEND_LIMIT]`. Payloads: 20,000 characters, 64 levels
  `[payload.ts:MAX_PAYLOAD_CHARS]`.
- Surface: 1,000 items `[surface.ts:MAX_SURFACE_ITEMS]` (enforced in `[rooms.ts:checkAgainstFacts]` as a
  read-then-write courtesy bound), 100 frames `[frames.ts:MAX_FRAMES]`, batches of 1 to 100
  `[surface.ts:MAX_SURFACE_BATCH]`, bodies of 8,000 characters. Blobs: 25 MB `[blobs.ts:MAX_BLOB_BYTES]`; image
  types are kept only when `sniffImageType` agrees `[blobs.ts:storedType]`.
- Reports: 10 per rolling 24 h, folded per target, resolved reports deleted after 180 days
  `[reports.ts:REPORTS_PER_DAY]`, `[reports.ts:REPORT_RETENTION_MS]`. Outside tasks: 3 open per caller, 7 days
  idle, 10 min before the seat hands off, 20 seat answers per UTC day `[outside.ts:MAX_OPEN_OUTSIDE_TASKS]`.
- Hosted seat: 8 wakes per hour `[store.ts:WAKES_PER_HOUR]`, 3 replies per question
  `[host.ts:REPLIES_PER_QUESTION]`, 4 attempts with 60 s, 300 s and 900 s retries `[host.ts:RETRY_MS]`, model
  calls aborted at 30 s `[host.ts:MODEL_TIMEOUT_MS]`.
- Action requests stay answerable 30 minutes, topic-room proposals 7 days `[action-state.ts:ACTION_REQUEST_TTL_MS]`;
  the first response wins and only `approved === true` counts as an approval `[action-state.ts:verdictOf]`.
- Decisions: 20 open per room, 3 open per opening seat, 5 revisions of one seat's vote on one decision
  `[decision.ts:MAX_OPEN_DECISIONS]`, `[decision.ts:MAX_OPEN_PER_SEAT]`, `[decision.ts:MAX_REVISIONS]`; an expiry
  from 5 minutes to 7 days `[decision.ts:MIN_DECISION_TTL_MS]`; a page of 50 by default and 100 at most
  `[decision.ts:DECISION_PAGE]`. Only a binding vote (`dash_session`, or an `action_response` with
  `human_approved: true`) counts, one per account `[decision.ts:capacityOfVote]`.

### Client side

- Push is never a dependency. `[bridge.ts:viaBus]` hands a member back to the long-poll `watch` from the shared
  cursor on bus failure; `[bus.ts:openBus]` turns every setup failure into `BusUnavailableError`;
  `[room-socket.ts:drive]` degrades to polling after 3 failures or a refused credential. Delivery is deduplicated
  by cursor (`[bridge.ts:watch]`, `[bus.ts:Sub.sentThrough]`, `[room-socket.ts:accept]`).
- `[bridge.ts:watch]` never creates a connection; a watcher whose connection is gone disarms instead.
  `[bridge.ts:showsEvictionOf]` trusts only `member_evicted` and `member_timed_out` event types, so a peer payload
  cannot forge an eviction.
- Sockets are created 0600 by narrowing the umask around `listen` (`[bus.ts:listen]`, `[door.ts:startDoor]`) in
  directories created 0700; those permissions are the door's only access check.
- `[bridge.ts:readLocalFile]` refuses symlinks, paths outside the upload root, non-regular files and files over
  `MAX_BLOB_BYTES`; `[bridge.ts:uploadRoot]` refuses an implicit root that is `/`, the home directory or one of
  its ancestors.
- `[credentials.ts:replaceFile]` writes through a 0600 temp file and an atomic rename; `[credentials.ts:writeServer]`
  refuses to write when the directory or file cannot be secured. `[signin.ts:BridgeAuth.saveCodeVerifier]` keeps
  the PKCE verifier in memory only, and the loopback listener compares `state` itself
  (`[signin.ts:makeListener.onRequest]`).

## Side Effects

- Durable Object storage. `SessionDO`: `session`, `cursor`, `e:<cursor>`, `sf:<key>`, member rows (`mb:`, `mu:`,
  `lb:`, `bf:`), `ik:` idempotency records, `bn:`/`bu:` bans, `sn:` stranger send counts, `ot:`/`oc:`/`ov`
  outside tasks, the decision index `dx:`/`dv:`/`dx-at`, outbox `ob:`/`ob_seq`/`due:`. `RegistryDO`: the
  prefixes listed under Interface (the room index `rm:`/`ri:` among them) plus its own outbox. `AuditDO`: SQL `entries` and `delivered`, KV `sink`, `settings`, `chain_anchor`, `due:sink`,
  `due:sweep`. `HostDO`: `state` and `pending`. Each of the four object types runs on a single alarm.
- Cross-object RPC: `SessionDO` to `RegistryDO` (`putJoinCode`, `dropJoinCode`, `releaseHostedRoom`,
  `putCreatorBan`, index drops on purge, `dropRoomIndex` among them), to `AuditDO.append`, and to `HostDO.wake`/`forget`; `HostDO` back to
  `SessionDO` (`appendHostEvent`, `eventsAfter`, `renewHostAllowance`, `seatSkipped`). The facade calls
  `RegistryDO.indexSession` with the room's `RoomIndexRow` on create, `unindexedRooms` and `indexRoom` on a
  backfill, `SessionDO.roomSummary` per listed room, and the operator's `AuditDO` for `appendOperatorAudit`.
- R2: the `BLOBS` bucket under `rooms/<sessionId>/<blobId>` `[blobs-r2.ts:R2BlobStore]`; a closed room's
  unnamed objects are swept and a purge deletes the prefix `[store-do.ts:SessionDO.#purgeIfDue]`.
- Outbound HTTP: the Anthropic Messages API (`https://api.anthropic.com/v1/messages`, or `MODEL_URL`)
  `[host.ts:callMessages]`; an org's SIEM sink, HMAC-signed, https only, redirects not followed
  `[audit-sink.ts:deliverBatch]`; email through the `SEND_EMAIL` and `INVITE_EMAIL` bindings
  `[reports.ts:reportMailer]`, `[invite-mail.ts:inviteMailer]`.
- Node server: listens on `PORT` (3900) and runs `sweep`, `tick` and `housekeep` every 60 s `[index.ts]`.
- Client filesystem: credentials under `$XDG_CONFIG_HOME/bellman` or `~/.config/bellman` (`credentials.json`,
  `credentials.lock`) `[credentials.ts:credentialsDir]`; inboxes under `~/.claude/bellman/inbox/<pid>/`
  `[inbox.ts:inboxRoot]`; bus sockets under `~/.claude/bellman/bus/` `[bus.ts:busRoot]`; door sockets under
  `~/.claude/bellman/door/` `[door.ts:doorRoot]`; reads `.bellman/room.yaml` from the working directory
  `[bridge.ts:loadRoomManifest]`.
- Client processes and network: a loopback HTTP listener on 127.0.0.1:51004-51008 and a detached browser launcher
  `[signin.ts:openBrowser]`; MCP over Streamable HTTP to `BELLMAN_URL` (default `https://mcp.bellman.sh/mcp`)
  `[channel.ts]`; WebSockets to `/ws` `[room-socket.ts:attempt]`; `ps` for parent pids `[inbox.ts:parentPid]`;
  `npm` and `claude --version` from the CLI `[cli.ts:update]`, `[doctor.ts:diagnose]`.
- Environment read. Server: `BELLMAN_KEYS`, `BELLMAN_HOSTED_SEAT`, `BELLMAN_HOSTED_SEAT_USERS`,
  `ANTHROPIC_API_KEY`, `MODEL_URL`, `PORT`, plus the secrets in `[worker.ts:WorkerEnv]`. Client: `BELLMAN_KEY`,
  `BELLMAN_URL`, `BELLMAN_DELIVERY`, `BELLMAN_INSTALL`, `BELLMAN_BUS`, `BELLMAN_NO_BROWSER`, `BELLMAN_JOIN_CODE`,
  `BELLMAN_UPLOAD_ROOT`, `BELLMAN_INBOX_ROOT`, `BELLMAN_BUS_ROOT`, `BELLMAN_DOOR_ROOT`,
  `BELLMAN_HOOK_WAIT_SECONDS`, `XDG_CONFIG_HOME`.
